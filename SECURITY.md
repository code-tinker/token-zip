# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| latest  | ✅        |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues.**

If you believe you have found a security vulnerability in Token-Zip, please report it privately via email:

**📧 [it-security@yingmi.cn](mailto:it-security@yingmi.cn)**

### What to include

Please provide as much of the following information as possible to help us understand and address the issue quickly:

- **Type of issue** (e.g. unauthorized access, information disclosure, denial of service, supply chain tampering, etc.)
- **Affected component** (e.g. compression pipeline, API proxy layer, configuration handling)
- **Steps to reproduce** the issue
- **Proof-of-concept or exploit code** (if available)
- **Impact assessment** — what an attacker could achieve

### Response timeline

- We will acknowledge receipt of your report within **3 business days**.
- We will provide an initial assessment and estimated resolution timeline within **7 business days**.
- We will notify you when the vulnerability is fixed.

### Disclosure policy

- We ask that you give us a reasonable time to address the issue before any public disclosure.
- We will credit security researchers who responsibly disclose vulnerabilities (unless you prefer to remain anonymous).
- We will work with you to determine whether a CVE should be requested.

## Scope

Security issues we want to hear about include:

- API key leakage or improper credential handling
- Authentication/authorization bypass
- Injection vulnerabilities (prompt injection, code injection, etc.)
- Supply chain / dependency vulnerabilities with meaningful impact
- Information disclosure of sensitive data

Out of scope: issues that only affect development environments or require physical access to the machine.
